# 版式与视觉规则

## 总原则

简历首先要让招聘方快速读懂，其次才是风格表达。美观不是装饰堆砌，而是信息层级、留白、重点和阅读路径的设计。

## 标准文本简历

适合大多数投递场景。

建议：

- 标题清楚
- 模块顺序稳定
- 每段经历 3-6 条要点
- 每条要点尽量不超过 2 行
- 技能按类别组织
- 时间、公司、职位格式统一

## ATS 友好版

当用户用于官网投递、招聘系统上传、Boss/猎聘附件投递时，建议使用。

建议：

- 单栏为主
- 标准模块名：个人信息、专业总结、核心技能、工作经历、项目经历、教育背景
- 不使用复杂表格、文本框、图片、图标、技能进度条
- 联系方式放正文顶部，不放页眉页脚
- 文件优先为 `.docx` 或可复制文本的 PDF

注意：ATS 兼容不是所有场景的硬性要求，但线上系统投递时应优先考虑。

## 视觉增强版

适合以下场景：

- 设计、品牌、市场、内容、创意岗位
- 作品集网站
- 直接发给业务负责人、猎头或熟人内推
- 线下面试携带

可以使用：

- 头像或照片预留区域
- 左右分栏
- 品牌色点缀
- 作品集链接区
- 个人标签区
- 项目卡片式摘要

但必须保证：

- 文字对比度足够
- 信息层级清楚
- 正文可复制
- 不用装饰遮挡内容
- 不因追求设计感牺牲阅读效率

## 头像规则

头像可用于视觉增强版，但不默认用于 ATS 友好版。

如用户希望预留头像，应输出类似结构：

```text
[头像区域：建议 1:1 圆形或圆角方形，位于左上角或侧栏顶部]
姓名
目标职位
联系方式
```

提示用户注意：

- 不同行业和地区对简历照片接受度不同
- 海外岗位通常不建议放照片
- 国内部分岗位、猎聘/脉脉档案、创意展示场景可使用专业头像

## HTML/CSS 简历支持

Markdown 文件适合承载规则和内容，但不适合直接实现复杂视觉简历。

如用户需要复杂、美观、带头像的简历，建议输出：

1. 完整简历内容
2. 视觉版式说明
3. HTML/CSS 页面结构或设计稿提示词

HTML/CSS 输出应包含：

- 固定页面宽度或 A4 比例
- 头像占位
- 左侧信息栏或顶部信息区
- 模块化经历区
- 打印样式建议
- 移动端或 PDF 导出注意事项

不要假设当前 Agent 一定能生成图片、PDF 或 DOCX；只能在环境支持时执行对应文件生成。
