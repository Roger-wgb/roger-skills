# 改写规则

## 核心目标

让企业快速看出：

1. 候选人做过什么
2. 用什么方法做的
3. 做到了什么结果
4. 为什么与目标岗位相关

## 改写公式

优先使用以下结构：

```text
动词 + 工作对象 / 项目任务 + 方法 / 工具 / 协作方式 + 量化结果 / 业务影响
```

示例：

```text
优化客户续费跟进流程，通过分层运营和风险标签管理，将高风险客户响应时间缩短 40%，推动续费率提升 12%。
```

## 成果表达优先级

优先写结果，不优先写职责。

低质量表达：

```text
负责客户沟通和项目推进。
```

高质量表达：

```text
主导 20+ 家企业客户上线推进，协调产品、交付和客户方关键用户，将平均上线周期从 45 天缩短至 30 天。
```

## 数据补充规则

可以引导用户补充以下数据：

- 金额：收入、成本、预算、合同额
- 比例：增长率、转化率、留存率、满意度
- 时间：周期、响应时长、提前交付时间
- 规模：用户数、客户数、团队人数、项目数量
- 质量：准确率、缺陷率、SLA、投诉率

如用户没有精确数据，可使用保守估算：

```text
约 30%
30% 以上
20-30%
建议用户核实后替换为准确数据
```

## 真实性边界

允许：

- 优化表达顺序
- 强化真实经历中的岗位相关部分
- 使用更专业的行业语言
- 对不确定数据做保守估算并标注

不允许：

- 编造公司、职位、项目、学历、证书
- 把参与写成主导
- 把团队成果全部写成个人成果
- 添加用户没有掌握的技能
- 为了匹配 JD 伪造经验

## 输出时的核实提示

凡是以下内容不确定，必须列为待核实：

- 估算数据
- 项目规模
- 业务影响
- 技术栈熟练度
- 证书和时间
- 具体奖项或排名
