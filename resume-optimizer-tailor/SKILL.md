# 简历优化与定制 Skill

## 使用场景

当用户希望优化、重写、定制或管理简历版本时使用本 Skill。典型需求包括：

- 优化已有简历，使企业一眼看出候选人与岗位要求匹配
- 针对某个 JD 生成一版完整定制简历
- 将普通职责描述改写为成果导向、数据化的表达
- 为技术岗、管理岗、应届生、转行、创意设计、学术 CV 等不同场景生成不同版本
- 优化简历整体结构、版式呈现、视觉层级和可读性
- 维护简历母本和多个岗位定制版本

## 基本原则

1. 默认使用中文进行分析、说明和交付；如用户要求英文简历，简历正文可输出英文。
2. 只基于用户提供的真实经历进行优化，不凭空编造项目、职位、公司、学历、证书或业绩。
3. 允许在用户缺少精确数据时进行保守估算，但必须标注为“估算/建议核实”，并优先引导用户补充真实数据。
4. 输出应以“完整简历”为主，不只给修改建议。
5. 美观和阅读体验是核心目标之一；ATS 兼容是重要参考，但不是所有场景的硬性约束。
6. 本 Skill 为通用 Agent Skill，不依赖任何特定平台、编辑器或工具链。

## 必要输入

优先获取以下信息：

- 用户现有简历或经历素材
- 目标岗位名称与 JD
- 求职方向、目标行业、目标城市或国家
- 用户职业阶段：应届生、初中级、资深、管理岗、高管、转行、学术、创意设计等
- 简历目标语言：中文、英文或双语
- 输出形态：标准文本简历、ATS 友好版、视觉增强版、HTML/CSS 版式说明、简历母本或岗位定制版

如果缺少现有简历或经历素材，应先要求用户提供。不要从零虚构一份完整简历。

## 工作流程

1. 判断用户目标：通用优化、岗位定制、版本管理、视觉增强或特殊模式。
2. 选择简历模式，参考 `references/resume-modes.md`。
3. 重构简历内容：定位、专业总结、技能、工作经历、项目经历、教育与证书。
4. 强化岗位匹配：提取 JD 关键词，突出真实匹配证据。
5. 改写成果表达：使用行动、方法、结果、数据组织经历，参考 `references/rewrite-rules.md`。
6. 设计呈现形式：根据投递场景选择标准版、ATS 友好版或视觉增强版，参考 `references/layout-and-visual-rules.md`。
7. 输出完整简历，并附上版本名称、适用岗位、修改重点和待用户核实项。
8. 如用户同时投递多个方向，按 `references/version-management.md` 建议建立母本和定制版本。

## 输出要求

默认输出结构：

```markdown
# 简历版本说明

- 版本名称：
- 目标岗位：
- 适用场景：
- 简历语言：
- 需要用户核实的信息：

---

# 完整简历

[输出可直接复制使用的完整简历正文]

---

# 本版优化重点

1.
2.
3.
```

如果用户要求视觉增强版，可额外输出：

- 版式结构说明
- 头像/照片预留区域建议
- 色彩、字体、边距、模块层级建议
- HTML/CSS 简历页面生成说明，参考 `references/html-resume-output.md`
